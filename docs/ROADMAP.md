## Phase 1 — 地図＋チャット＋編集可能な旅程 MVP

目標: 地図を見ながら候補を相談し、国内・海外の旅行日程を自分で編集・確認できる。

### 実装順と成果物

1. **準備 gate**: 追跡済み環境/生成物、公開 LLM キー参照、旧 endpoint、依存サポート、API handler を別変更で是正。保存許諾付き地点 provider と初期対応都市・手段を決める。課金額承認まで fixture/manual mode。
2. **共通旅程モデル**: Trip/Day/Place/Stop/Leg と schemaVersion/revision。手動追加・削除・並べ替え・時刻/滞在時間編集・休息枠・取消。
3. **地図連動**: place/stop の ID 共有、カード/ピン選択、確定/候補の見分け、保存権利付き地点のみ保存。supported mode の経路、未計算の明示。
4. **chat 提案**: server LLM adapter、schema 検証、根拠・不確実性・差分表示。「適用」で反映し手動変更保全。
5. **保存と検証**: 端末内保存、JSON export/import と全削除、国内/海外各 1 都市で言語・time zone・通貨を検証。対応地域表、mock CI、回数/費用 guard。

### 非対象

共同編集、同行者アカウント、健康関連情報収集、個人 profile、全世界 POI の完全対応、公共交通の自動時刻表、ライブ混雑/天候、予約/決済、Azure の導入、offline map、public 共有、旅行安全の保証。

### 受入基準

- 国内と海外の各 1 架空旅行 fixture で、chat 候補→地図→旅程の同一 ID 連動と追加/却下/適用/取消が E2E で通る。live 対応の主張は別途 provider coverage を検証した地域だけ。
- 地図/リストの双方向選択、順序・時刻・滞在時間変更、更新後の再描画。地図障害時も手動編集を継続できる。
- refresh と export/import で保存可能な旅程が復元され、temporary provider 結果が storage/export/log に残らない。無許諾なら保存を止め理由を示す。
- 候補は確認状態、出典、取得日時、対象日、推定幅を表示。未解決地点、no route、手段未対応を捏造しない。
- LLM timeout/不正 JSON/429 でも既存旅程を維持。LLM secret が browser bundle にない。費用上限の並行要求と100%停止を mock で検証する。
- DST/日付変更線/複数通貨、キーボード・モバイルの主要操作が通る。secret なし build と依存点検が完了。

出口: fixture/manual MVP と live MVP の対応範囲を区別して報告。provider 許諾・予算・セキュリティ gate 未解決なら live 公開を見送る。

## Phase 2 — 同行者の条件と合意調整

目標: 各同行者の希望を尊重し、条件の衝突を見える形で調整する。

### 対象と設計

- 本人が受諾する招待、owner/editor/viewer、本人が所有する必須/希望条件。予算、興味、徒歩/移動負荷、暑さ回避、混雑回避、休息、宿泊の別室希望を任意入力。
- 条件は private 初期値。合意画面へ共有するルールと範囲を本人が選ぶ。病名や理由を求めない。
- 決定的検証で必須を満たす候補を優先。満たせない場合は `unsatisfied` と衝突条件を示す。必須を無断で希望へ緩和しない。
- 希望は参加者ごとの充足/未充足とトレードオフを示し、単一の平均点で不利益を隠さない。shared 条件だけを使い共有理由を生成する。
- 複数案（訪問削減、時間帯変更、予算調整、休息、別行動/合流、別室）を提示。別行動は参加者別 stop、集合場所/現地時刻、連絡確認を明示。宿泊割当は見積りで、予約しない。
- 混雑/暑さは provider 選定と鮮度 gate 後に取得。データなしでは不明表示と手動調整。交通渋滞を観光混雑扱いしない。
- 影響を受ける参加者全員の明示同意で適用。条件/予算/案変更で投票を無効化し再確認。未回答を承認と扱わない。
- 共有 DB は認証/認可 gate 後。端末データを無断 upload しない。revision 競合は差分を再提示。

架空例: 参加者 A の必須が「夕方の集合」、B の希望が「静かな施設」、旅行全体に予算上限がある場合、午前の別行動と午後の合流を二案提示。理由や実在人物の事情は含めない。

### 非対象

健康/交際の個人情報収集、非公開情報の推測・自動共有、相手による同意代行、病名ベースの分類、診断、安全保証、無断条件緩和、自動予約/決済、同意なし自動適用、全国/全世界の混雑予測保証。

### 受入基準

- 架空参加者の必須/希望/予算/休息/移動上限を入力・本人のみ編集できる。別室/別行動/集合案を旅程と地図へ表せる。
- 衝突を検出し、代替案で誰のどの shared 条件が未充足か示す。必須違反は適用を止めるか、本人が条件を変更し再合意する。
- 未回答/拒否のある案を適用しない。案や条件 version の変更で旧同意を使えず、重複送信でも一度しか適用しない。
- owner/editor/viewer と本人 private 条件の IDOR テストが通る。private 条件・理由は API/共有画面/export/log に出ない。派生説明の推測リスクを点検する。
- 天候/混雑の古い・欠損・未対応データを表示し、休息を含む代替案が手動編集可能。元通貨と換算時刻付き予算を比較できる。
- 複数端末の revision 衝突で既存の編集を消さず、招待失効/参加撤回でアクセスを停止する。

出口: shared 条件だけで合意できること、private な理由を要求しないことを確認。P3 の機微情報を先取りしない。

## Phase 3 — 同意ベースの高度な個別配慮と現地再計画

目標: 通常機能を維持したまま、本人が任意に求める配慮と現地変更に対応する。

### 対象と順序

1. **同意 gate**: 項目/目的/提供先/期限/撤回の UI、法的/運用評価、private store/鍵管理、削除/backup 期限、LLM 等の保持条件を確定。拒否しても通常利用可能。
2. **最小の個別配慮**: 本人が承認した抽象ルールを使う。機微原文の収集を標準にしない。本人以外、同行者や Trip owner に自動共有しない。
3. **現地変更**: 施設閉鎖、予定の遅れ、天候、利用者の任意入力から代替案。常時位置追跡や身体状態の推定はしない。
4. **再計画**: 変更した区間のみ提案し、locked stop、予約済み予定、集合、休息、必須条件、予算を保つ。差分と根拠の再確認時刻を表示。
5. **撤回/障害**: consent 失効で利用を停止し未適用案を無効化。外部 outage や通信断は既存旅程と手動編集へ退避。課金を自動追加しない。

### 非対象

診断、治療助言、疾病推定、緊急監視、旅行可否の判定、安全保証、wearable/医療記録の自動取得、同行者への自動開示、同意の代行、予約変更や購入の自動実行。

### 受入基準

- 同意なし/期限切れ/撤回後に private データの取得・LLM 使用・再計画を拒否する。通常の旅行計画は継続できる。
- 項目別・目的別・提供先別の同意と処理履歴が確認でき、本人が削除/撤回できる。backup の失効と復元時の再削除を検証する。
- private 情報が共有 DTO/地図/説明/export/log に漏れないことを権限・派生情報を含め検証。実個人情報を fixture に使わない。
- 閉鎖/遅延/天候変化の架空 fixture で、二つ以上の比較案または「案なし」を返す。未変更区間・locked stop を保持し、差分適用前に affected participants の再合意を得る。
- stale データ、通信断、no route、予算上限、矛盾条件では無理な案を確定せず、未確認事項と手動代替を表示する。

出口: privacy/consent/削除 gate と再計画テストを完了して段階公開。高度な配慮の導入が診断や安全保証にならないことを文言と挙動で確認する。
